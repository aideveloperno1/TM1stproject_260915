# private/ — 실제 분석 근거 파일 보관 (공개 금지)

## 역할

데이터 분석 담당이 실제 카드 소비데이터로 계산한 `review_evidence.json`을 서비스에서 내부 시연·검증할 때만 두는 곳이다.
이 README를 제외한 모든 파일은 `.gitignore`로 git에서 제외된다.

## 기준 문서

- 최종기획서 8장: 카드 원자료와 비공개 파생정보를 외부 LLM에 보내지 않는다
- 최종기획서 10장, 워크플로우 S06: 공개 배포는 합성 결과만 포함한다
- 참가신청서류 보안관리 서약서 2항: 제공 데이터의 인터넷 유포·복사 등 어떠한 유출도 금지

## 둘 파일

| 파일 | 상태 | 내용 |
|---|---|---|
| `review_evidence_real_v{버전}.json` | 데이터 담당 전달 후 | 워크플로우 9-3장 형식의 실제 결과. `data_kind`는 `"real"` |
| `data_version_notes.txt` (선택) | 필요 시 | 받은 날짜, 데이터 담당이 알려준 버전·변경점 메모. 수치는 적지 않는다 |

## 지켜야 할 원칙

1. **이 폴더의 파일을 git에 추가하지 않는다.** `git add -f`로 강제 추가하지 않는다.
2. **파일 이름에 `_real_`을 넣는다.** 폴더 밖으로 실수로 옮겨도 `.gitignore`의 `*_real_*.json` 규칙이 한 번 더 막는다.
3. **결과 파일을 직접 고치지 않는다.** 숫자·구조가 틀리면 데이터 담당에게 입력조건·근거 ID·잘못된 표시·기대 결과를 전달하고 새 버전을 받는다 (워크플로우 9-3장).
4. **외부 AI 도구에 파일 내용을 붙이거나 읽히지 않는다.** Claude Code 등으로 작업할 때도 이 폴더는 열지 않는다.
5. **클라우드 LLM 설정과 함께 쓰지 않는다.** 실제 자료 + 클라우드 LLM 조합은 차단 대상이다 (checks.md LLM 전달 자료).
6. 서비스가 이 파일을 읽을지, 어떻게 선택할지는 개발 담당이 진행 상황을 보고 결정한다 (checks.md 보류 항목). 코드 기본값은 `resources/evidence/`의 합성 파일이다.

## 확인 방법

- 커밋 전 `git status`에 `private/` 아래 파일이 보이지 않아야 한다.
- `scripts/check_public_bundle.py`(예정)가 추적 중인 파일에서 `"data_kind": "real"`을 찾으면 실패한다.
