# `private/` — 실제 분석 근거 파일 보관 (공개 금지)

> 최신화: 2026-09-17

## 이 폴더는 무엇인가

데이터 분석 담당이 **실제 카드 소비데이터로 계산한 결과 파일**을 두는 곳입니다. 서비스에서 실제 자료로 확인·시연할 때만 씁니다.
이 README를 빼고 **이 폴더의 파일은 git에 올라가지 않도록** 막혀 있습니다(공개 저장소이기 때문).
서비스는 이 폴더 안의 파일을 **자동으로 "실제 자료"로 보고 보호**합니다.

## 파일 목록

| 파일 | 하는 일 (쉬운 말) | 언제 보거나 고치나 | 상태 |
|---|---|---|---|
| `README.md` | 이 문서. 폴더를 다루는 규칙 | 규칙이 바뀔 때 | 있음 (git에 올라가는 유일한 파일) |
| `review_evidence_real_v{버전}.json` | 데이터 담당이 만든 **실제 결과 파일**. 서비스가 2~5단계에서 읽음 | 데이터 담당에게 새 버전을 받았을 때 교체. **직접 고치지 않음** | 확정본 전달 대기 |
| `data_version_notes.txt` | 받은 날짜·버전·변경점 메모(수치는 적지 않음) | 파일을 받을 때 | 선택 |

## 자세한 설명 (개발자용)

### 기준 문서

- 최종기획서 8장: 카드 원자료와 비공개 파생정보를 외부 LLM에 보내지 않는다
- 최종기획서 10장, 워크플로우 S06: 공개 배포는 합성 결과만 포함한다
- 참가신청서류 보안관리 서약서 2항: 제공 데이터의 인터넷 유포·복사 등 어떠한 유출도 금지

### 서비스에서 쓰는 방법

```
PSM_EVIDENCE_PATH=private/review_evidence_real_v1.json
PSM_LLM_PROVIDER=none
```

`.env`에 위 두 줄을 두고 `uv run --env-file .env policy-signal-map`으로 실행한다. 설정하지 않으면 코드 기본값인 `resources/evidence/`의 합성 파일을 읽는다.

### 실제 자료로 보는 기준 (`evidence/loader.py`의 `is_real_evidence`)

아래 중 하나라도 맞으면 실제 자료로 보고, 클라우드 LLM과 함께 켜지 못하게 막는다.

1. 경로에 `private` 폴더가 있음
2. 파일 이름에 `_real_`이 있음
3. 파일 안 `data_kind`가 `synthetic`이 **아님** — 약속된 값은 `real`이지만 다른 이름이 들어와도 실제 자료로 본다. 파일이 형식 검사에서 거부돼도 원문에서 확인한다 (9/17 보강)

### 지켜야 할 원칙

1. **이 폴더의 파일을 git에 추가하지 않는다.** `git add -f`로 강제 추가하지 않는다.
2. **파일 이름에 `_real_`을 넣는다.** 폴더 밖으로 실수로 옮겨도 `.gitignore`의 `*_real_*.json` 규칙이 한 번 더 막는다.
3. **결과 파일을 직접 고치지 않는다.** 숫자·구조가 틀리면 데이터 담당에게 입력조건·근거 ID·잘못된 표시·기대 결과를 전달하고 새 버전을 받는다 (워크플로우 9-3장).
4. **외부 AI 도구에 파일 내용을 붙이거나 읽히지 않는다.** Claude Code 등으로 작업할 때도 이 폴더의 내용은 열지 않는다(구조·일치 여부만 확인하는 스크립트는 값을 출력하지 않게 만든다).
5. **LLM 설정:** 실제 자료 + 클라우드 LLM은 코드가 차단한다. 실제 자료 + 로컬 LLM은 **허용**(사용자 결정 9/17, `checks.md` 1장)이지만, 화면 숫자를 분석 결과와 대조하는 동안(2차 연결 확인)은 `PSM_LLM_PROVIDER=none`으로 둔다.

### 확인 방법

- 커밋 전 `git status`에 `private/` 아래 파일이 보이지 않아야 한다.
- `scripts/check_public_bundle.py`가 추적 중인 파일에서 `private/` 파일, `_real_` 이름, `synthetic`이 아닌 `data_kind`를 찾으면 실패한다. push 전에 실행한다.
