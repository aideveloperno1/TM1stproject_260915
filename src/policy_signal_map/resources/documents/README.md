# resources/documents/ — 보완 기획안·요청서 Markdown 양식

## 역할

`document/render.py`가 채워 넣는 Jinja2 양식. 문서 문장 구성을 바꿀 때 코드를 고치지 않고 양식만 고친다.

## 만들 파일

| 파일 | 상태 | 내용 |
|---|---|---|
| `plan.md.j2` | 예정 (9/18) | 보완 기획안 전체 (본문 + 별첨 1·2) |
| `request.md.j2` | 예정 (9/18) | 별첨 3 정밀 분석 요청서 초안 (옵션 D 선택 시 `plan.md.j2`가 include) |

## `plan.md.j2` 구성

```
# 보완 기획안 — {사업명}

> 생성일 {YYYY-MM-DD} · 자료: {시연용 합성 수치 | 자료 버전} · 이 문서는 담당자 확인 전 초안입니다

## 요약
- 변경 N건 · 추가 확정 필요 N건 · 원안 유지 N개 장

## 1. 사업 개요
## 2. 목적·대상
## 3. 일정
## 4. 혜택·사용처
## 5. 모집·정산
## 6. 예산 상태
## 7. 성과 측정계획
## 8. 추가 확인사항

---
## 별첨 1. 변경 전후
| 장 | 원안 | 보완안 | 근거 | 담당자 선택 |

## 별첨 2. 근거와 해석 한계
- 근거 ID · 범위(전국 참고 등) · 기간 · 자료 버전 · 합성/실제
- 한계 목록

## 별첨 3. 정밀 분석 요청서 (초안)      ← 옵션 D 선택 시만
```

- 변경 줄 끝 표기: `〔변경 · 근거 R07-A〕`, 추가 확정 필요 값: `**[추가 확정 필요]**`
- 장에 내용이 없으면 "원안에 기재 없음 **[추가 확정 필요]**"
- 사용자 입력은 모두 `| md_escape` 필터를 거친다

## `request.md.j2` 구성

- 요청 목적, 분석 대상(참여 점포 목록), 기간·단위, 필요 지표, 확인 필요(점포 식별 가능 여부·자료 제공·계약 조건·비용)
- 마지막 줄 고정: `※ 초안이며 계약·자료 제공이 확정된 것이 아닙니다.`
- 참여 점포의 BC 결제 실적은 현재 CSV로 조회할 수 없고, 점포의 모든 결제가 사업 참여자 결제와 같지 않다는 문장 포함 (최종기획서 4-4)

## 원칙

- 양식에 수치를 직접 적지 않는다. 모든 값은 `document/builder.py`가 넘긴다
- "성공", "효과 입증" 등 평가 단정 표현을 쓰지 않는다
- 외부 편집기(메모장, VS Code, Typora)에서 열어 표·목록이 깨지지 않는지 확인한다 (워크플로우 12장 Markdown 내보내기)
